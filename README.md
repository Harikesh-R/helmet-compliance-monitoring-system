# Helmet Compliance Monitoring System

A computer vision-based helmet compliance monitoring system built using YOLO11 and the Ultralytics framework. The system detects workers, helmets, and instances of helmet non-compliance from images and video.

## Project Overview

The goal of this project is to develop an AI-based computer vision system that can automatically identify whether workers are wearing safety helmets.

The system uses object detection to identify three classes:

- Helmet
- No Helmet
- Worker

The trained model can be used to analyze images and videos and generate annotated outputs with detected objects and confidence scores.

## Problem Statement

In workplaces such as construction sites and industrial environments, safety helmets are essential for protecting workers from head injuries.

Manual monitoring of helmet compliance can be difficult, especially in large or crowded work environments.

This project aims to automate helmet compliance monitoring using computer vision and deep learning.

## Model

The project uses the pretrained YOLO11 Nano model as the base model.

The model was fine-tuned on the helmet detection dataset.

### Training Configuration

| Parameter | Value |
|---|---|
| Model | YOLO11 Nano |
| Image Size | 640 × 640 |
| Epochs | 10 |
| Batch Size | 16 |
| GPU | NVIDIA Tesla T4 |
| Framework | Ultralytics |
| PyTorch | 2.11.0+cu128 |
| CUDA | Available |

## Training Results

After 10 epochs of training, the model achieved the following validation results:

| Metric | Result |
|---|---:|
| Precision | 0.852 |
| Recall | 0.561 |
| mAP@50 | 0.575 |
| mAP@50-95 | 0.332 |

### Class-wise Validation Results

| Class | Precision | Recall | mAP@50 | mAP@50-95 |
|---|---:|---:|---:|---:|

The trained model was also tested on a video.

The inference pipeline detects objects frame-by-frame and produces an annotated video showing the detected classes.

The output video demonstrates the model detecting:

- Helmets

- Workers

The generated video was produced using the trained YOLO11 model.

Limitations

The current model has significantly better performance on the Helmet and No Helmet classes than on the Worker class.

The Worker class has very few annotated instances in the validation and test sets, which results in low recall and mAP for that class.

Therefore, the current system should primarily be considered a prototype for helmet compliance detection rather than a production-ready safety monitoring system.
